# 건물 문서 AI 색인 연동 설계

## 목표

관리자가 건물 운영 문서를 업로드·수정·삭제할 때 S3 파일과 `rule_documents` 상태를 일관되게 관리하고, AI 색인 API에 최신 문서 목록을 전달한다.

## 범위

- 문서 업로드 완료 후 AI 색인 작업 요청
- 여러 문서 등록 시 마지막 요청에 `valid_doc_ids` 전달
- 문서 삭제 시 현재 유효한 문서 ID 목록으로 AI 색인 정리 요청
- AI 호출 실패가 문서 저장 자체를 롤백하지 않도록 분리
- 색인 요청 결과를 추적하고 재시도할 수 있는 구조
- 기존 FE 업로드 흐름과 Presigned S3 업로드 방식 유지

문서 목록·상세·수정·삭제 화면의 전체 UI 구현은 별도 범위로 분리한다. 이번 연동은 기존 문서 등록 API가 색인 요청을 발생시키는 데 필요한 백엔드 계약을 우선 구현한다.

## 외부 AI 계약

```http
POST /api/v3/ai/indexing/jobs
Content-Type: application/json
```

요청 예시:

```json
{
  "building_id": 101,
  "doc_id": "notice-002",
  "title": "승강기 정기 점검 안내",
  "file_key": "s3://zipsai-files/buildings/101/notice-002.pdf",
  "valid_doc_ids": ["rule-2026", "notice-001", "notice-002"]
}
```

응답은 `202 Accepted`와 빈 본문을 성공으로 처리한다. AI 서비스 오류, 네트워크 오류, 타임아웃은 문서 DB 트랜잭션과 분리하여 색인 실패 상태로 기록한다.

## 처리 흐름

### 신규·수정 문서

1. FE가 `POST /api/v1/files`로 Presigned PUT URL을 요청한다.
2. FE가 S3에 파일을 업로드한다.
3. FE가 `PATCH /api/v1/files/{attachmentId}`로 업로드 완료를 확정한다.
4. 백엔드는 해당 첨부파일을 `UPLOADED`로 변경하고 건물 문서를 저장하거나 갱신한다.
5. 백엔드는 문서별로 AI 색인 요청을 보낸다.
6. 여러 문서 요청 중 마지막 요청에만 현재 유효한 `valid_doc_ids`를 포함한다.

### 삭제 문서

1. 백엔드는 문서 삭제를 논리 삭제 또는 프로젝트의 기존 삭제 정책에 따라 처리한다.
2. 삭제 후 해당 건물의 유효 문서 ID 목록을 조회한다.
3. `doc_id` 없이 `building_id`와 `valid_doc_ids`만 포함한 AI 색인 정리 요청을 보낸다.

## 책임 분리

- `FileService`: S3 업로드 준비와 업로드 완료 검증
- 문서 서비스: `rule_documents` 저장·수정·삭제와 유효 문서 목록 계산
- AI 색인 클라이언트: 외부 API URL, JSON 요청, `202` 성공 판정, 오류 변환
- 색인 상태 저장: 문서 저장 트랜잭션과 외부 호출 결과를 분리하여 재시도 가능하도록 관리

외부 AI 호출을 문서 저장 트랜잭션 안에서 동기 실행하지 않는다. AI가 일시적으로 unavailable이어도 문서 등록 결과는 보존되어야 한다.

## 설정

AI 호출 주소와 인증 정보는 코드에 하드코딩하지 않는다.

```yaml
app:
  ai:
    base-url: ${AI_API_URL}
    api-key: ${AI_API_KEY:}
```

AI API가 별도 인증 헤더를 사용하지 않는 환경에서는 `api-key`를 비워둘 수 있다.

## 오류 처리 및 재시도

- `202 Accepted`: 색인 요청 접수 성공
- `400`, `422`: 요청 계약 오류로 기록하고 자동 재시도하지 않음
- `429`, `500`, `502`, `503`, `504`, 네트워크 오류: 재시도 가능 상태로 기록
- AI 실패가 발생해도 `rule_documents` 저장 상태는 유지
- 같은 문서에 대한 중복 색인 요청은 문서 ID와 버전 또는 최신 updated time을 기준으로 추적

## 검증 기준

- 허용되지 않은 파일은 문서 저장 전에 거부된다.
- 업로드 완료되지 않은 첨부파일은 문서 등록과 색인 대상이 될 수 없다.
- 색인 요청에는 해당 건물의 문서만 포함된다.
- 마지막 문서 요청의 `valid_doc_ids`에는 삭제되지 않은 문서만 포함된다.
- AI 202 응답과 실패 응답이 각각 올바른 상태로 기록된다.
- AI 장애가 발생해도 문서 조회와 재시도 대상 확인이 가능하다.
